# GenericArrayType 支持建议

## 目标

建议优先支持以下两类泛型数组反序列化场景：

1. 类型变量数组字段：

```java
class ArrayResponse<T> {
    private T[] data;
}

class RowArrayResponse extends ArrayResponse<Row> {
}
```

期望 `RowArrayResponse` 中的 `data` 按 `Row[]` 反序列化。

2. 参数化组件数组：

```java
Response<List<Row>[]>
```

期望 JSON 数组反序列化为 `List[]`，每个元素按 `List<Row>` 读取。

非目标：`Map` 的非 String key 不需要支持。

## 当前问题

当前失败点主要集中在 `GenericArrayType`：

1. `TypeResolver.resolveType` 目前只处理 `TypeVariable` 和 `ParameterizedType`，没有递归处理 `GenericArrayType`。
2. `DsonContext.parseReader` 在遇到 `GenericArrayType` 时直接创建 `NewArrayReader`，没有先结合 `typeVariableContext` 解析组件类型。
3. `NewArrayReader.initialize` 对 `GenericArrayType` 的假设过窄：它只接受最终组件类型是 `ParameterizedType` 的情况，遇到 `T[]` 这类最终组件是 `TypeVariable` 的数组会失败。
4. 数组创建需要的是可擦除的运行时组件 `Class`，而元素读取需要的是完整的泛型组件 `Type`。当前实现没有把这两件事清晰拆开。

## 建议做法

### 1. 先让 TypeResolver 支持 GenericArrayType

在 `TypeResolver.resolveType(Type type, Map<TypeVariable<?>, Type> resolved)` 中增加 `GenericArrayType` 分支。

核心逻辑：

```java
if (type instanceof GenericArrayType gat) {
    Type component = resolveType(gat.getGenericComponentType(), resolved);
    if (component instanceof Class<?> componentClass) {
        return Array.newInstance(componentClass, 0).getClass();
    }
    return new GenericArrayTypeImpl(component);
}
```

这样：

```java
T[]，T = Row
```

可以解析成：

```java
Row[]
```

而：

```java
List<Row>[]
```

可以保留为：

```java
GenericArrayType(component = List<Row>)
```

需要新增一个简单的 `GenericArrayTypeImpl`，类似当前的 `ParameterizedTypeImpl`。

建议同时给自定义的 `ParameterizedTypeImpl` 和 `GenericArrayTypeImpl` 实现 `equals`、`hashCode`、`toString`，否则作为缓存 key 时不稳定，虽然不是本问题的直接原因。

### 2. DsonContext.parseReader 先解析 Type，再分派 reader

当前逻辑是先判断 `GenericArrayType`，再解析类型。建议改成：

1. 先用 `TypeResolver.resolveType(type, typeVariableContext)` 得到 `resolvedType`。
2. 用 `resolvedType` 查询和写入 reader 缓存。
3. 按 `resolvedType` 分派：
   - `GenericArrayType` -> `NewArrayReader`
   - `Class` 且 `isArray()` -> `NewArrayReader`
   - `ParameterizedType` -> 根据 raw type 分派

关键点：不要把未解析的 `T[]`、`List<T>[]` 直接作为最终 reader 初始化依据。

### 3. NewArrayReader 拆开“数组运行时组件 Class”和“元素读取 Type”

数组反序列化需要两个信息：

1. `componentClass`：用于 `Array.newInstance(componentClass, len)`。
2. `componentType`：用于 `dsonContext.parseReader(componentType, context)`。

建议 `NewArrayReader.initialize` 统一处理：

```java
Type resolvedType = TypeResolver.resolveType(type, typeVariableContext);
Type componentType = getImmediateComponentType(resolvedType);
Class<?> componentClass = eraseToArrayComponentClass(componentType);

this.componentType = componentClass;
this.componentReader = dsonContext.parseReader(componentType, typeVariableContext);
```

其中 `getImmediateComponentType`：

```java
if (arrayType instanceof Class<?> clazz && clazz.isArray()) {
    return clazz.getComponentType();
}
if (arrayType instanceof GenericArrayType gat) {
    return gat.getGenericComponentType();
}
throw new IllegalArgumentException(arrayType.toString());
```

其中 `eraseToArrayComponentClass`：

```java
if (type instanceof Class<?> clazz) {
    return clazz;
}
if (type instanceof ParameterizedType pt) {
    return (Class<?>) pt.getRawType();
}
if (type instanceof GenericArrayType gat) {
    Class<?> nested = eraseToArrayComponentClass(gat.getGenericComponentType());
    return Array.newInstance(nested, 0).getClass();
}
throw new IllegalArgumentException(type.toString());
```

这样可以覆盖：

```java
Row[]              -> componentClass = Row.class, componentType = Row.class
List<Row>[]        -> componentClass = List.class, componentType = List<Row>
List<Row>[][]      -> componentClass = List[].class, componentType = List<Row>[]
```

### 4. 保持元素读取使用完整泛型 Type

不要把 `List<Row>[]` 的元素 reader 简化为 `List.class`。

数组创建时可以使用擦除后的 `List.class`，但元素读取必须使用完整的：

```java
List<Row>
```

否则数组能创建出来，但数组元素里的 `Row` 会丢失泛型信息。

## 建议验收用例

至少保留以下测试：

```java
@Test
public void shouldResolveGenericArrayField()
{
    TestRowArrayResponse response = Dson.fromString(TestRowArrayResponse.class, """
            {
              "data": [
                {"name": "alpha"},
                {"name": "beta"}
              ]
            }
            """);
    Assert.assertEquals("alpha", response.data()[0].getName());
    Assert.assertEquals("beta", response.data()[1].getName());
}
```

```java
@Test
public void shouldDeserializeParameterizedComponentArrayTypeArgument()
{
    Type type = new TypeUtil<Response<List<Row>[]>>() {}.getType();
    Response<List<Row>[]> response = Dson.fromString(type, """
            {
              "data": [
                [{"name": "alpha"}],
                [{"name": "beta"}]
              ]
            }
            """);
    Assert.assertEquals("alpha", response.data()[0].get(0).getName());
    Assert.assertEquals("beta", response.data()[1].get(0).getName());
}
```

可以额外增加多维数组：

```java
Response<List<Row>[][]>
```

这个用例能验证 `GenericArrayType` 递归处理是否完整。

## 风险点

1. `NewArrayReader.fromString` 当前使用 `Object[]` 接收临时数组，因此它只适合引用类型数组。泛型数组本身不会是原始类型数组，所以本次支持范围内问题不大。
2. 如果把未解析的 `TypeVariable` 或 `GenericArrayType` 放进共享 reader 缓存，后续不同泛型上下文可能产生错误复用。建议缓存 key 使用解析后的 `resolvedType`。
3. `ParameterizedTypeImpl` / `GenericArrayTypeImpl` 如果不实现 `equals` 和 `hashCode`，缓存命中率会差，也更难排查 reader 复用问题。

## 推荐实施顺序

1. 给 `TypeResolver.resolveType` 增加 `GenericArrayType` 支持。
2. 调整 `DsonContext.parseReader`：先解析 `Type`，再查缓存和分派 reader。
3. 重写 `NewArrayReader.initialize` 的类型分析逻辑，拆分 `componentClass` 与 `componentType`。
4. 跑数组相关目标测试。
5. 再跑已有泛型测试，确认普通 `Response<T>`、`List<T>`、`Map<String, T>` 没有回归。
